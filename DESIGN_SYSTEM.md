# Design system

A warm, workshop-inspired identity for a studio that makes practical tools:
graphite and bone neutrals, one signal-orange accent used sparingly, a
drafting-table visual language (hairlines, corner registration marks, mono
annotations, a pegboard dot grid) and a distinct hue per product line.

All tokens live in `src/styles/global.css` and are exposed to Tailwind as
utilities. Never hard-code hex values in components.

## Brand

- **Working name:** Plainwork (change in `src/config/site.ts`).
- **Mark:** a selection frame around a solid block — "the work, in focus".
  Source: `src/components/brand/LogoMark.astro`; favicons/app icons are
  generated by `npm run assets:icons`.
- **Wordmark:** the name in Mona Sans, weight 650, lowercase, tracking −0.035em.
- **Headline (hero):** "Practical tools for the unglamorous work." Alternatives
  considered: "Software for the work behind the work", "The tedious parts, made
  simple", "Tools that take care of the tedious parts". The chosen line is the
  most memorable, pairs with the name, and implies the outcome without
  over-promising. Edit it in `src/config/site.ts` (`hero`).

### Voice

Plain, specific, calm. Short sentences. Describe what something does, not the
results it will produce. Always state status honestly ("In development",
"Coming soon"). Avoid hype ("revolutionize", "supercharge", "seamless",
"next-generation", "AI-powered" as a slogan).

## Color

Defined in OKLCH. Dark is the default theme; light is optional (toggle in the
header, stored in `localStorage`). Contrast ratios (WCAG 2.x) below were
computed for both themes; the e2e suite re-checks every page with axe.

| Token | Utility | Dark | Light | Use |
| --- | --- | --- | --- | --- |
| `--canvas` | `bg-canvas` | `#0d0c0b` | `#faf9f6` | page background |
| `--surface` | `bg-surface` | `#131311` | `#ffffff` | cards |
| `--surface-2` | `bg-surface-2` | `#1a1917` | `#f3f1ed` | raised controls, hovers |
| `--surface-3` | `bg-surface-3` | `#242320` | `#eae8e3` | pressed states |
| `--line` / `--line-strong` | `border-line` | 8.5% / 16% bone | 10% / 19% ink | hairlines |
| `--ink` | `text-ink` | `#f2f0eb` (17:1) | `#171613` (17:1) | headings, body emphasis |
| `--ink-2` | `text-ink-2` | `#b3b1ab` (9:1) | `#4f4d48` (8:1) | body text |
| `--ink-3` | `text-ink-3` | `#8d8a85` (5.7:1) | `#65635e` (5.7:1) | meta text, labels |
| `--accent` | `text-accent`, `bg-accent` | `#fb8435` (7.9:1) | `#b84500` (5.1:1) | the mark, focus rings, small highlights |
| `--ok` / `--caution` / `--danger` | `text-ok`… | | | status badges only |

**Product-line tones.** Each line has a `hue` in `businesses.yaml`. Any element
with `style="--tone-h: <hue>"` gets `--tone`, `--tone-soft`, `--tone-faint`
and `--tone-line`, computed per theme (`L 0.80 / C 0.11` dark, `L 0.48 / C 0.13`
light) so every hue keeps AA contrast. Current hues: operations 255 (blue),
WordPress 200 (teal), employer 150 (green), templates 85 (amber), family 350
(rose). The accent orange (≈50) is reserved for the brand.

**Rules:** one accent per view; no gradients beyond the faint radial glows
already defined; no purple neon; status colors only on badges.

## Typography

- **Mona Sans** (variable, weight 200–900) for everything; **Geist Mono** for
  labels, numbers and annotations. Both self-hosted (latin subset, ~63 KB
  total), SIL Open Font License; Astro generates metric-matched fallbacks so
  swapping fonts causes no layout shift.

| Utility | Size | Line height | Tracking | Weight | Use |
| --- | --- | --- | --- | --- | --- |
| `text-display-1` | 41.6 → 86.4 px (fluid) | 0.98 | −0.042em | 640 | page H1 |
| `text-display-2` | 32 → 52.8 px | 1.04 | −0.034em | 620 | section titles |
| `text-display-3` | 23.2 → 32 px | 1.14 | −0.024em | 600 | sub-sections, empty states |
| `text-lead` | 17 → 19.2 px | 1.6 | — | 400 | intro paragraphs |
| body | 16 px | 1.6 | — | 400 | default |
| `.eyebrow` | 12 px mono, uppercase | 1 | 0.06em | 500 | section labels |
| `.prose` | 17 px | 1.75 | — | 400 | Markdown articles, max 42rem |

Headings use `text-wrap: balance`; paragraphs `text-wrap: pretty`.

## Layout and spacing

- Container: `.container-site` — max 76rem, side gutters `clamp(1rem, 4vw, 2rem)`
  (16 px on phones).
- Sections: `.section` — vertical padding `clamp(4.5rem, 9vw, 8rem)`, separated
  by a top hairline (`border-t border-line`).
- Grids: 12 columns on desktop for asymmetric splits (7/5, 5/7); 6-column bento
  for product lines that adapts to 1–5 visible lines.
- Spacing follows Tailwind's 4 px scale.

## Shape and elevation

- Radius: cards `--radius-card` (14 px), controls `--radius-control` (10 px),
  pills fully rounded.
- Dark theme elevation = borders + a 1 px inner highlight; light theme adds
  soft layered shadows (`--shadow-1`, `--shadow-2`).

## Signature elements

- **Section index rule** (`SectionHeading`): `01 ──────── PRODUCT LINES` —
  numbers follow the order sections actually render.
- **Corner marks** (`CornerMarks`): drafting registration marks on feature
  cards, the task finder, the updates panel.
- **Pegboard dot grid** (`.dot-grid` + `.fade-mask-radial`): page headers, hero.
- **Product-line glyphs and illustrations** (`LineGlyph`, `LineArt`): CSS-only
  compositions that suggest the work (document → fields, plugin toggles,
  deadline calendar, file stack, flagged message). No fake data or metrics.
- **Task finder**: the hero's command-palette-style component.
- **Footer wordmark**: oversized, faded, cropped.

## Motion

- Tokens: `--ease-out-expo` (entrances), `--ease-out-quart` (UI), 160–320 ms
  for UI, 700–900 ms for entrances.
- `.enter` — load-in for small elements only (never the LCP headline).
- `.reveal` — fade-up on scroll (IntersectionObserver), with a CSS failsafe.
- Hover: cards lift 2 px with a pointer-following glow (`.spotlight`, fine
  pointers only); line illustrations animate only while hovered/focused.
- Page transitions: native cross-document View Transitions (no JavaScript).
- `prefers-reduced-motion: reduce` disables all of the above.

## Accessibility rules

- WCAG 2.2 AA contrast in both themes; visible 2 px accent focus rings.
- One `<h1>` per page; landmarks labelled; skip link; keyboard support for
  menus, search (combobox pattern), filters and dialogs (native `<dialog>`).
- Touch targets ≥ 36 px (most 44 px).
- Every interactive enhancement degrades to plain links/forms without JS.

## Do / don't

- Do use semantic tokens and existing components before adding new ones.
- Do keep one accent element per viewport.
- Don't add stock photography, AI imagery, fake dashboards or invented numbers.
- Don't add animation libraries or UI frameworks.
